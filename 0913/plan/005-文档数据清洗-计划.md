## 3. ⚠️ 三个必须避开的陷阱

这三条是本计划的核心风险,写在这里供你判断我的方案是否稳妥。

### 陷阱 1:校歌简谱和表格**都使用 `|` 符号**

```
校歌简谱 : 5. 5  5. 5  5.  | 3  | 1  3  | 2  -  | ...     ← | 在中间
表格数据 : | 层次 | 专业 | 学费 (元/年) | ...              ← | 在行首
```

**后果**:如果清洗规则写成「删除含 `|` 的行」→ **表格会被一起删光**;反过来写成「含 `|` 的行都是表格」→ **简谱会被当成表格保留**。

**对策**:用**行首位置**区分 —— 表格行匹配 `^\s*\|`,简谱行的 `|` 不在行首。

### 陷阱 2:全局套用"低汉字占比就删"会**误删表格**

表格里有两类行汉字占比极低:

```
| ---- | ---- | ---- | ---- | ---- |        ← 汉字占比 0.00
| 本科 | 少数民族预科班 | 5040 | - | / | - |  ← 汉字占比约 0.16
```

**后果**:如果对全文套用"汉字占比 < 0.5 就删",表格分隔行和数字密集的数据行会被全部删掉,表格就废了。

**对策**:**限定作用范围** —— 汉字占比规则**只在「集美学校校歌」章节内生效**,不碰其他章节。同时硬性规则「以 `|` 开头的行永不删除」。

### 陷阱 3:目录内容**不能靠内容特征识别**

```
本科新生入学须知 01
安全防范知识 01
```

这些行看起来和正文没区别(有汉字、有数字)。**只能靠位置判断**:`## 目录` 标题之后、下一个标题之前。

## 4. 方案设计

### 4.1 处理流程

```
读原始文档
    ↓
① 按行拆分
② 定位「校歌」章节范围 → 删曲调行,保留歌词  ← 需求1
③ 定位「目录」章节范围 → 整段删除              ← 需求2
④ 表格行保护(以 | 开头的一律不动)            ← 需求3
    ↓
重组为清洗后文本 → 交给 buildChunks() 分块 → 向量化
```

### 4.2 需求 1:过滤校歌曲调

**范围界定**:从 `## 集美学校校歌` 这一行开始,到**下一个标题行**(`^#{1,4}\s`)之前结束。

**范围内逐行判定**:

| 行的类型 | 判定规则 | 处理 |
|---|---|---|
| 标题行 | 匹配 `^#{1,4}\s` | 保留 |
| 空行 | 全空白 | 保留 |
| **歌词行** | 汉字占比 ≥ **0.5** | **保留** |
| **曲调行** | 汉字占比 < 0.5 | **删除**(简谱 / 调号 / 拍号 一网打尽) |

汉字占比 = 汉字字符数 ÷ 总字符数(用 `[\u4e00-\u9fff]` 统计)。

**为什么用占比而不是"不含汉字"?** 因为调号和拍号里**带汉字**:

```
1=F(或G)      → 含"或",不含汉字规则会漏掉
2/4(庄严)     → 含"庄严",同样漏掉
```

占比规则能一次性覆盖三类曲调行,不用给它们写特例。实测阈值 0.5 分离得很干净(0.29 / 0.80)。

### 4.3 需求 2:过滤目录

**范围界定**:从 `^#{1,4}\s*目录\s*$` 这一行开始,到**下一个标题行**之前结束,**整段删除**(含标题行本身)。

- 支持 `# 目录` / `## 目录` / `### 目录` 等各种级别
- 如果文档里出现多个「目录」章节,全部处理
- 位置靠**标题文本精确匹配**「目录」二字,避免误伤正文里的"目录"一词(正文中该词不会单独成标题)

### 4.4 需求 3:保持表格完整

分两层保护:

**第一层(清洗阶段)**:硬性规则 —— **以 `|` 开头的行永不被任何清洗规则删除**。即使将来加新的清洗规则,表格也不会被误伤。

**第二层(分块阶段)**:当前 `splitLongText()` 对超过 900 字的段落会**每 900 字硬切**。如果表格超过 900 字,就会被从中间切断、表头和数据分离。

> 实测现在两处表格是 421 / 268 字符,**都小于 900,暂时不会被切**。
> 但这是"碰巧安全",不是"保证安全" —— 换一个更大的文档就会出问题。

**对策**:给 `splitLongText()` 加表格感知 —— 检测到该段落是 Markdown 表格时,**整段作为一个块输出,不做任何切分**(即使超长)。

检测方式:段落中**连续多行以 `|` 开头**,即判定为表格。
