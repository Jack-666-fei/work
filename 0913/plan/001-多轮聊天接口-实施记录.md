## 3. 实施中踩到的三个坑

### 3.1 `-parameters` 编译标志(直接导致 500)

给 `GET /api/chat/{id}/messages` 第一次发请求时返回 **HTTP 500**:

```
java.lang.IllegalArgumentException: Name for argument of type [java.lang.String] not specified,
and parameter name information not available via reflection.
Ensure that the compiler uses the '-parameters' flag.
```

原因:IDEA 的 `.idea/compiler.xml` 里配置了 `options="-parameters"`,而手动 `javac` 没带这个标志,`@PathVariable` 就无法通过反射拿到参数名。

> **注意一个假象**:用例 1、2 当时是**通过**的,因为它们走 `@RequestBody`(record 反序列化),不依赖参数名解析。所以"改了代码,基本功能一测就过"会掩盖这个问题——直到调用带路径变量的端点才暴露。

处置(双保险):
1. 源码改为 `@PathVariable("conversationId")` 显式命名 —— 让代码**不再依赖编译标志**
2. 手动编译命令补上 `-parameters` —— 与 IDEA 行为对齐

### 3.2 这个环境的 `pwsh` 其实是 Windows PowerShell 5.1

`$PSVersionTable.PSVersion` = **5.1.26100.9168**,不是 PowerShell 7。

后果:`Get-Content` 默认按 **GBK** 解码,导致:
- 读取 `target/cp.txt` 时 201 条 classpath 条目**全部**判定为"不存在"(实际全部存在)
- 直接捕获 `curl.exe` 的中文输出会变成乱码

规避方式(本次全程采用):

```powershell
# 写:显式 UTF-8 无 BOM
[System.IO.File]::WriteAllText($p, $s, (New-Object System.Text.UTF8Encoding($false)))
# 读:显式 UTF-8
[System.IO.File]::ReadAllText($p, [System.Text.Encoding]::UTF8)
# curl 一律 -o 落盘再读,不要直接捕获 stdout
curl.exe -s -o out.json ...
```

> 这也**回溯解释了**为什么历史遗留的 `evidence/02_top10_query.json` 里中文全是乱码(`"鏀惰垂鏍囧噯"` = "收费标准")——数据本身没问题,是捕获环节的编码问题。

补充:PowerShell 里**别名优先级高于函数**,自定义函数若命名为 `R`,会被内置的 `Invoke-History` 别名覆盖。本次已改名为 `ReadU8` / `WriteU8`。

### 3.3 `-Dfile.encoding=UTF-8` 参数被 PowerShell 拆坏

直接写 `& $java -Dfile.encoding=UTF-8 -cp ...` 会报 `ClassNotFoundException: /encoding=UTF-8`。加引号即可:`& $java "-Dfile.encoding=UTF-8" -cp ...`。

## 4. 环境根因:WSL VM 一直被回收(重点)

这是"之前跑过环境、感觉没问题"背后**真正缺的东西**。

### 4.1 现象

`docker compose up -d` 报告三个容器全部 `Running`,`docker compose ps` 也显示端口映射 `0.0.0.0:19530->19530/tcp`。但:

- Windows 侧 `19530 / 9091 / 9000 / 9001` **全部未监听**
- `curl http://127.0.0.1:9091/healthz` → 连接失败(HTTP 000)
- `wsl -l -v` 显示 Ubuntu **Stopped**,却又能在 WSL 里执行 `docker ps`
- WSL 内 `docker ps` 显示容器状态永远是 **"Up 1 second"**

### 4.2 根因

每次调用 `wsl.exe -d Ubuntu -- <cmd>` 都会**冷启动一个 WSL VM**,命令执行完 VM 随即被回收。下次调用重新启动,dockerd 依 `restart: unless-stopped` 把容器再拉起一遍——所以容器**永远处于启动后 1 秒**、永远到不了 healthy、端口也来不及转发到 Windows。

**没有任何进程持有这个 VM,它就一直在被销毁重建。**

这解释了 `milvus-deploy/pipeline.log` 里整段历史:

```
cycle 1 : milvus not fully healthy in 140s, retry
cycle 1 : milvus proxy up after ~80s
cycle 1 : app not ready or engine bounced, retry
```

当时写的 `run_import.ps1` → `run_stable_import.ps1` → `run_detect_v3.ps1` 三代"等待稳定窗口"的重试流水线,**都在对抗症状而不是根因**。所谓"engine bounced"并不是 Milvus 不稳定,而是探测进程一退出、VM 就被回收了。

### 4.3 解法

用一个长驻进程把 VM 钉住,再启动 compose:

```powershell
# 后台常驻,持有 WSL VM
wsl.exe -d Ubuntu -- bash -lc "sleep 86400"
```

效果:

| 指标 | 修复前 | 修复后 |
|---|---|---|
| `wsl -l -v` | Stopped | **Running** |
| 容器状态 | Up 1 second(反复重启) | 稳定 healthy |
| `healthz` | HTTP 000 | **OK,约 15s 就绪** |
| 主机端口 19530/9091/9000/9001 | 全部未监听 | **全部监听** |

> 启动 Milvus 本身并没有历史记录里那么慢。VM 被持有后,从 `compose up` 到 `healthz OK` 只需约 **15 秒**。

### 4.4 顺带修正:默认数据库名不是 `_default`

```
POST /v2/vectordb/collections/list  {"dbName":"_default"}
→ {"code":800,"message":"database not found[database=_default]"}

POST /v2/vectordb/collections/list  {}
→ {"code":0,"data":["jmu_handbook"]}

POST /v2/vectordb/databases/list    {}
→ {"code":0,"data":["default"]}
```

这个 Milvus v3 实例的默认库名是 **`default`**,不是 `_default`。历史脚本 `run_detect_v3.ps1` 的 `Test-Proxy` 用的正是 `{"dbName":"_default"}`,它的"代理存活判定"其实是错的——只是因为该请求仍返回 HTTP 200(错误码在 body 里),判定才偶然生效。建议后续统一改用 `{}` 探测。

**向量库状态正常**:`jmu_handbook` 集合存在,此前导入的数据仍在。

## 5. 如何复现本次运行结果

环境前置(LM Studio 已在 1234 运行,模型 `google/gemma-4-e2b` 与 `text-embedding-nomic-embed-text-v1.5` 均已加载):

```powershell
# 1) 钉住 WSL VM(必须,否则容器反复重启)
wsl.exe -d Ubuntu -- bash -lc "sleep 86400"      # 以后台作业方式常驻

# 2) 起 Milvus
Set-Location <工作目录>\milvus-deploy
docker compose up -d
# 等 healthz 返回 OK(约 15s)

# 3) 编译(注意 -parameters)
$rag = '<项目路径>\rag'
$cp  = [System.IO.File]::ReadAllText("$rag\target\cp.txt",[System.Text.Encoding]::UTF8).Trim()
$jdk = "$env:USERPROFILE\.jdks\openjdk-23.0.2"
$srcs = Get-ChildItem "$rag\src\main\java" -Recurse -Filter *.java | ForEach-Object { $_.FullName }
& "$jdk\bin\javac.exe" -encoding UTF-8 --release 21 -parameters -proc:full -nowarn `
    -cp "$rag\target\classes;$cp" -d "$rag\target\classes" $srcs

# 4) 运行
& "$jdk\bin\java.exe" "-Dfile.encoding=UTF-8" -cp "$rag\target\classes;$cp" com.wuyunbin.rag.RagApplication
```

> 手工编译只是为了不依赖 IDEA。正常开发请在 IDEA 里构建(其 `.idea/compiler.xml` 已含 `-parameters`)。

## 6. 已知遗留 / 后续建议
