### 3.2 指标

| 指标 | 定义 |
|---|---|
| **Recall@k** | 7 道可答题中,正确章节出现在返回结果里的比例(k = topK) |
| **MRR** | 平均倒数排名 = Σ(1/首次命中排名) ÷ 题数 |
| **平均返回条数** | 每次检索实际返回多少块 —— 召回率相同时,返回越少噪声越小 |
| **幻觉数** | 3 道库外题中,模型编造答案的数量(正确行为是回答「未提及」) |

### 3.3 扫描网格

- **topK** ∈ {3, 5, 8, 10, 15}
- **similarityThreshold** ∈ {0.0, 0.5, 0.6, 0.65, 0.70}

共 25 组 × 7 道可答题 = **175 次检索**,实测总耗时 **18.1 秒**。

## 5. 结论:本机最佳组合

```
最优参数: chunk=900, topK=10, similarityThreshold=0.6, temp=0.7
```

### 选择理由

1. **topK=10 是召回率的拐点**:3/5→42.9%,8→57.1%,**10→71.4%**,15→71.4%(不再提升)
2. **topK=15 不选**:召回率与 10 相同,但平均多返回 **4.3 条**无关内容,白白污染上下文
3. **阈值 0.6 而非 0.0**:两者召回率完全相同(71.4%),但 0.6 平均少返回 1 条噪声 —— **同等召回下噪声更少**
4. **阈值不能再高**:0.65 召回就掉到 57.1%,0.70 直接灾难(5/7 的题返回空结果)

## 6. 与参考机的对比(本作业的核心发现)

| | 参考机 | **本机** |
|---|---|---|
| 最优 topK | **5** | **10** |
| 最优阈值 | 未标注 | **0.6** |
| 分块大小 | 800 | 900 |
| Recall@k | **100%** | **71.4%** |
| MRR | **1.00** | **0.389** |
| 幻觉数 | 0 | 0 ✅ |

**同样一套 RAG 流程,最佳 topK 差了整整一倍,召回率差了近 30 个百分点。**

### 为什么本机的 topK 必须更大?

因为**本机的嵌入模型对中文几乎没有区分能力**。实测该模型给中文文本的相似度分数分布:

```
查询「接站」 vs 接站程序片段(相关)  →  0.6131
查询「接站」 vs 档案转移片段(无关)  →  0.6857   ← 不相关的反而更高!
```

所有中文文本的分数都**挤在 0.65~0.73 这个窄带里**,相关与不相关几乎分不开。后果:

1. **正确答案的排名被随机化** —— 无法靠分数排序把它排到前面
2. **阈值窗口极窄** —— 设 0.70 就把绝大多数内容滤光(实测 5/7 道题返回空)
3. **只能靠加大 topK「兜」** —— 既然排不准,就多捞一些进来碰运气

**这就是为什么本机 topK=10,而参考机 topK=5 就够。**

### 硬件如何影响这个结论

```
4 GB 显存  →  只能跑 2B 小模型 + 英文嵌入模型
           →  中文嵌入质量差
           →  分数区间窄、区分度低
           →  topK 必须加大、阈值必须压低
```

**换一块显存更大的显卡 → 能跑更强的中文嵌入模型(bge-m3 / Qwen3-Embedding)→ 分数会拉开 → 最优参数会完全改变。**

所以这个作业的注意事项说得对:**每台机器的"最佳"不可照搬。**

| ID | 是否命中 | 命中排名 | Top1 返回章节 |
|---|---|---|---|
| F01 | ✓ | **第 1 位** | 集美学校校歌 |
| F02 | ✗ | — | 四、档案转移 |
| F03 | ✗ | — | 学校基础信息 |
| F04 | ✓ | 第 8 位 | 应征地 |
| F05 | ✓ | 第 10 位 | 一、本科新生入学须知 |
| F06 | ✓ | **第 1 位** | 生活用品要求 |
| F07 | ✓ | 第 2 位 | 入学资格复查 |

**注意 F04 和 F05 的命中排名是第 8 和第 10 位** —— 虽然进了 topK,但排在很后面。这说明:
- 加大 topK 确实能"捞到"正确答案,但**排序质量依然很差**
- 如果正确片段排在第 10 位,而上下文预算有限,模型很可能忽略它

## 11. 建议的后续改进(按收益排序)

| # | 措施 | 预期效果 |
|---|---|---|
| **1** | **换支持中文的嵌入模型**(bge-m3 / Qwen3-Embedding / bge-large-zh) | 分数拉开 → 排序变准 → topK 可降回 5,召回率有望到 90%+ |
| 2 | 调小分块上限(900 → 500~600) | 块更聚焦,减少无关内容稀释向量 |
| 3 | 给过短的块(<50 字)合并到相邻块 | 本机有 13 个块不足 50 字,语义太稀 |
| 4 | 加 chunk overlap(10~20%) | 避免答案正好被切在块边界 |
| 5 | 引入重排序(rerank) | 用交叉编码器对 topK 结果重排,直接解决"排不准"问题 |

> **第 1 条是根本解。** 其他都是在小显存约束下的缓解手段。
