## 2. 实现方式:有限状态机

### 2.1 状态定义

文档的每一行都处于且仅处于三个状态之一,状态决定该行如何被处理:

| 状态 | 含义 | 对该行采取的动作 |
|---|---|---|
| `NORMAL` | 普通章节 | **保留** |
| `SONG` | 校歌章节 | **删曲调行,留歌词** |
| `TOC` | 目录章节 | **删除**(含标题行) |

### 2.2 状态转移图

```
                    遇到标题行
                        │
          ┌─────────────┴─────────────┐
          │  根据标题内容判定目标状态   │
          │  含"校歌"  → SONG         │
          │  等于"目录" → TOC         │
          │  其它      → NORMAL       │
          └─────────────┬─────────────┘
                        │
      ┌─────────────────┼─────────────────┐
      ▼                 ▼                 ▼
 ┌─────────┐      ┌──────────┐      ┌─────────┐
 │ NORMAL  │      │   SONG   │      │   TOC   │
 │ 全部保留 │      │ 只留歌词  │      │ 整段删除 │
 └─────────┘      └──────────┘      └─────────┘
```

**关键规则:只有标题行能触发状态转移**;其余行只产生"动作",不改变状态。初始状态为 `NORMAL`。

### 2.3 核心代码

```java
enum SectionState { NORMAL, SONG, TOC }

SectionState state = SectionState.NORMAL;   // 初始状态
for (String line : lines) {

    // ① 状态转移：只有标题行能触发
    if (isHeading(line)) {
        state = classify(line);             // 转移函数
    }

    // ② 动作：由当前状态决定去留
    boolean keep;
    switch (state) {
        case TOC    -> keep = false;                          // 目录：连标题一起删
        case SONG   -> keep = isHeading(line) || line.isBlank()
                             || isTableRow(line)               // 表格保护
                             || cjkRatio(line) >= 0.5;         // 歌词留存，曲调删除
        default     -> keep = true;                            // NORMAL：全部保留
    }

    // ③ 输出
    if (keep) kept.add(line);
}
```

转移函数(状态机里唯一的"转移边"):

```java
private SectionState classify(String headingLine) {
    if (TOC_HEADING.matcher(headingLine).matches())  return SectionState.TOC;
    if (SONG_HEADING.matcher(headingLine).matches()) return SectionState.SONG;
    return SectionState.NORMAL;
}
```

### 2.4 实际状态转移过程(4 次)

```
#1  第  9行  NORMAL → SONG    「## 集美学校校歌」
#2  第 23行  SONG   → NORMAL  「## 校徽说明」
#3  第 36行  NORMAL → TOC     「## 目录」
#4  第 48行  TOC    → NORMAL  「# 一、本科新生入学须知」
```

其余标题(`## 校长致辞`、`## 三、新生报到注意事项` 等)都是 `NORMAL → NORMAL`,**不产生转移**。

> 这个转移次数作为 `stateTransitions` 字段对外暴露,可在日志和预览接口里看到 —— 方便确认状态机确实按预期在工作。

### 2.5 为什么用状态机

| | 状态机 | 之前的"扫标题定范围"写法 |
|---|---|---|
| "当前在哪一节" | **显式状态变量** | 隐式(藏在循环范围 `i..end` 里) |
| 扫描方式 | 单遍流式 | 需要先找到章节边界 |
| 加新规则 | 加一个状态 + 转移边 | 加一个 `else if` 分支 |
| 规则多/需嵌套时 | 更清晰 | 会变笨重 |

对当前这 3 条规则,两种写法都可行。但状态机的优势在于**可扩展**:若后续要加"删页眉页脚""跳过参考文献""表格内特殊处理"等规则,只需在 `SectionState` 里加状态、在 `classify()` 里加转移条件。

## 3. 判定规则细节

### 3.1 校歌曲调 vs 歌词:用「汉字占比」区分(仅 `SONG` 状态下生效)

```
歌词行 : 大家勿忘，大家勿忘。                    汉字占比 0.80
曲调行 : 6  5  | 3  1  | 2  5. 4  | 3. 2  1 ||  汉字占比 0.00
调号   : 1=F(或G)                              汉字占比 0.14
拍号   : 2/4(庄严)                             汉字占比 0.29
```

**阈值取 0.5** —— 实测歌词最低 0.80、曲调最高 0.29,中间有很宽的安全区。

**为什么不用「不含汉字就删」?** 因为调号和拍号里**带汉字**(`或`、`庄严`),那个规则会漏掉它们。占比规则一次覆盖三类,不用写特例。

### 3.2 目录:只能靠位置识别

目录内容行(`本科新生入学须知 01`)表面看和正文没区别,**不能靠内容特征判断**。

在状态机里这天然就解决了:一旦标题匹配「目录」就转入 `TOC` 状态,**直到下一个标题才转出**,期间所有行(含标题本身)一律删除。

## 4. ⚠️ 实施中避开的两个陷阱

### 陷阱 1:校歌简谱和表格都用 `|` 符号

```
简谱 : 5. 5  5. 5  5.  | 3  | 1  3  | 2  -      ← | 在行中间
表格 : | 层次 | 专业 | 学费 (元/年) | …          ← | 在行首
```

如果规则写成「删除含 `|` 的行」→ **表格被删光**;写成「含 `|` 就是表格」→ **简谱留下来**。

**对策**:统一用**行首位置**区分 —— 表格匹配 `^\s*\|`。

### 陷阱 2:汉字占比规则不能全局套用

表格里有大量低汉字行:

```
| ---- | ---- | ---- | ---- |        汉字占比 0.00
| 本科 | 少数民族预科班 | 5040 | …    汉字占比约 0.16
```

**全局套用会把表格删废。**

**对策**:在状态机里这被自然限制住了 —— 汉字占比规则**只在 `SONG` 状态下执行**,`NORMAL` 状态下的表格完全不受影响。再叠加「以 `|` 开头的行永不删除」的硬保护。

> 这正是状态机的价值:规则的作用域由状态精确限定,不会误伤其他区域。

### 5.2 表格保护(需求 3 的第二层)

清洗只保证表格**不被删**,还需要保证**不被切**。

`splitLongText()` 原本对超过 900 字的段落**每 900 字硬切**。表格一旦超过 900 字,就会被从中间切断 —— 表头和数据分离,检索命中的可能只是一堆没有列名的数字。

**新增保护**:检测到段落是 Markdown 表格(连续 ≥ 2 行以 `|` 开头)时,**整段作为一个块输出,即使超长也不切**。

> 实测两处表格是 438 / 286 字,都小于 900,原本就不会被切。
> 但这是"碰巧安全" —— 换个更大的文档就会出问题,所以还是加了保护。
