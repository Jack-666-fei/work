## 2. 日志立竿见影的价值

这是本次最值得记录的一点。**日志上线后第一次对话,就当场把 `002` 里花了很多功夫才定位的检索问题摆在了明面上。**

问「新生要把户口迁到学校吗?」时,`rag-retrieval.log` 输出:

```
--- #1 排名=1 分数=0.7253 章节="新生报到核查"            长度=84 字
--- #2 排名=2 分数=0.6994 章节="三、新生报到注意事项"      长度=286 字
--- #3 排名=3 分数=0.6993 章节="3、新生在报到点办理入学手续程序"  长度=358 字
--- #4 排名=4 分数=0.6951 章节="户口迁移相关规定"         长度=535 字   ← 正确答案
--- #5 排名=5 分数=0.6931 章节="港口与海岸工程学院"        长度=69 字    ← 完全无关
分数区间: 最高=0.7253 最低=0.6931
```

一眼可见三件事:

1. **正确答案被埋在第 4 位**,排在三个无关片段之后
2. **极差只有 0.0312**(0.6931~0.7253),这个区间内基本没有区分度
3. **完全无关的「港口与海岸工程学院」拿到 0.6931**,与正确答案的 0.6951 只差 0.002

在 `002` 里,为了得到这个结论,我们不得不:另外写脚本 → 手工调 `/api/kb/search` → 再单独调 embedding 接口算余弦相似度。

**现在这些信息每次对话都自动落盘。**

> 另一组数据(检索接口新增的 score 字段)
> 查 `户口迁移`:rank=1「六、户口迁移(同本科政策)」0.6697,
> rank=2「港口与海岸工程学院」0.6519,rank=3「户口迁移相关规定」0.6495
> —— 同样是无关内容排在有内容之前。

### 3.3 配置项

```properties
rag.logs.dir=logs
rag.logs.retrieval-level=full        # off | brief | full | prompt
rag.logs.retrieval-max-chars=0       # 0 = 不截断
rag.logs.low-score-threshold=0       # 0 = 关闭低分告警
rag.logs.export.enabled=true
rag.logs.export.localhost-only=true
rag.logs.tail.max-lines=5000
```

**关于低分告警**:按讨论结论,**默认关闭**。上面那组数据已经说明了原因 ——
当前嵌入模型对中文的相似度普遍挤在 0.69~0.73,相关与不相关几乎分不开,
设任何阈值都只会变成噪音。等换成中文嵌入模型、分数拉开后再启用这个配置项。

## 4. 召回日志格式

### 4.1 输出位置:控制台 + 独立文件(2026-09-10 补充)

初版把 `RAG_RETRIEVAL` logger 设成 `additivity="false"` 且**只挂了文件 appender**,
结果在 IDEA 里启动后端时,终端**看不到**召回的文档 —— 只能事后去翻日志文件。

已修正为:

```xml
<logger name="RAG_RETRIEVAL" level="DEBUG" additivity="false">
    <appender-ref ref="CONSOLE"/>          <!-- 新增:IDEA 终端直接可见 -->
    <appender-ref ref="RETRIEVAL_FILE"/>   <!-- 保留:关闭程序后仍可回溯/导出 -->
</logger>
```

- **控制台**:在 IDEA 里 Run 后端,召回内容直接打在 Run 窗口
- **文件**:`logs/rag-retrieval.log`,便于日后回溯与导出
- `additivity="false"` 仍然保留 —— 否则会冒泡到 root,把主日志 `rag.log` 也刷屏

**改动无需重新编译**,只改了资源文件。在 IDEA 里**重新 Run 一次**即可(IDEA 会自动把
`src/main/resources` 拷到 `target/classes`)。

> 若 IDEA 控制台中文显示为乱码:在 Run Configuration 的 VM options 里加
> `-Dfile.encoding=UTF-8`(与本项目日志的 UTF-8 输出对应)。

### 4.2 格式

```
==================== 检索开始 ====================
会话: c10f8344-b0d8-4898-83ed-9be56e5cefaa
查询原文: 新生要把户口迁到学校吗？
参数: topK=5 相似度阈值=0.0 集合=jmu_handbook
结果: 命中 5 条, 检索耗时 45ms
--- #1 排名=1 分数=0.7253 章节="新生报到核查" 长度=84 字 ---
> 新生报到核查
> 新生报到后由学校统一安排资格审查及体检复查。……
--- #4 排名=4 分数=0.6951 章节="户口迁移相关规定" 长度=535 字 ---
> 户口迁移相关规定
> (1)但未领到身份证的、或身份证遗失的，必须到当地派出所开具相关证明……
...
分数区间: 最高=0.7253 最低=0.6931
去重: 命中 5 条 → 有效 5 条（丢弃重复正文 0 条）
==================== 检索结束 ====================
```

正文每行带 `> ` 前缀,因此**多行内容仍可逐行 grep**,不会破坏日志结构:

```powershell
# 找某次请求召回了什么
Select-String -Path logs\rag-retrieval.log -Pattern 'req=71a83db0'

# 只看章节名和分数,不看正文
Select-String -Path logs\rag-retrieval.log -Pattern '--- #'
```

## 5. 排查用法

按 `requestId` 串起一次请求的全部日志:

```powershell
# 响应头 X-Request-Id 给出 ID,然后:
Select-String -Path logs\rag.log -Pattern '71a83db0'
```

想看某次检索的完整召回内容 → `logs\rag-retrieval.log`
想知道某次问答耗时 → `logs\rag.log` 里的 `对话完成: ... 耗时=xxxx ms`
想看错误堆栈 → `logs\rag-error.log`

推荐流程:出错时先 `GET /api/logs/export` 拿 zip,不用去翻目录。

## 6. 本次踩到的两个点

### 6.1 日志文件能否在应用运行时读取

应用运行时用 `[System.IO.File]::ReadAllText` 读日志会失败,报"正由另一进程使用"。

**但这不是独占锁**,实测:

| 方式 | 结果 |
|---|---|
| `[System.IO.File]::ReadAllText` | ❌ 失败 |
| `Get-Content -Raw` | ✅ 成功 |
| `FileStream` + `FileShare.ReadWrite` | ✅ 成功 |
| `Copy-Item` | ✅ 成功 |

失败的是该方法**默认只请求 `FileShare.Read`**,而 Logback 的句柄未授予这种共享模式。

**结论:在 IDEA 或记事本里直接打开日志文件没问题**,只是 PowerShell 的某些读法要注意。
应用自身的 `tail` 接口用 Java NIO 读取,完全正常。

### 6.2 手动构建必须拷贝资源

`logback-spring.xml` 是通过手动 `javac` 构建的,而 javac **不会拷贝 `src/main/resources`**。
每次编译后必须执行:

```powershell
Copy-Item "$rag\src\main\resources\*" "$rag\target\classes\" -Recurse -Force
```

否则日志配置根本不生效(IDEA 构建会自动做这一步)。
